## 4. 작업 규칙 (요약 — 자세한 건 방법론 문서)

1. **산식을 다시 짜지 마라.** 검증 스크립트는 index.html에서 함수를 문자열로
   추출해 쓴다(`tools/*.js` 전부 이 방식). 두 곳에 두면 반드시 어긋난다.
2. **승률만 보지 마라.** 반드시 같은 구간 기준선 대비 %p로. 컷을 걸 때는
   "지워지는 표본의 성적"을 따로 찍어라 — 승률이 올라도 지운 게 승자 집단이면 착시다.
3. **표본 기준**: 50+ 조정 가능 / 30~50 방향만 / 15~30 참고 / 15 미만 신뢰 불가.
   같은 종목·날짜 겹치면 유효 표본 절반 이하.
4. **과거 hist는 절대 수정 금지** (append-only). hist_fields는 꼬리 추가만 허용.
5. 전·후반 반으로 갈라 양쪽 다 기준선을 넘어야 채택. 한쪽만 좋으면 장세 잔상.
6. 레버리지 상품 판정은 1배 환산(levX 나누기)이 기본.

## 5. 도구 모음 (전부 읽기 전용, 저장소 루트에서 실행)

```
node tools/formula-lab.js      # 추세·반등 게이트 변형 비교 (대조군 P0 = 현재 배포값)
node tools/gate-variants.js    # 방어섹터 목록 후보 비교
node tools/phase-table.js      # 국면별(강세/중립/주의/약세) 승률
node tools/qqq-lab.js          # QQQ 단독 예측력 + 국면 분류 후보
node tools/sector-weak.js      # 약세장 섹터별 실측
node tools/ichi-compare.js     # 일목 적용 시나리오 비교
```

P0(대조군)가 사이트 검증표와 같은 숫자를 내는지가 도구 자체 검사다.
다르면 도구가 깨진 것이지 산식이 깨진 게 아니다.
